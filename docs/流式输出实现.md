# 流式输出（Streaming）实现说明

mini-nanobot 的「逐 token 流式回复」功能文档。目标：让 `ConsoleChannel`
在 LLM 生成时实时把 token 打到终端，而不是等整条消息生成完才一次性输出。

## 1. 现状与思路

项目里其实已经留好了流式的「骨架」，只是没接通：

- `MessageBus` 的 `OutboundMessage` 早就有 `event` 字段，取值
  `"final" | "delta" | "stream_end" | "error"`
  （见 [bus.py](../src/mini_nanobot/bus.py)）。

- `ChannelManager._dispatch_outbound` 也已经按 `event` 路由：
  `delta` → `channel.send_delta`，`stream_end` → `channel.send_delta_end`，
  其余 → `channel.send`
  （见 [channels/manager.py](../src/mini_nanobot/channels/manager.py)）。

- `BaseChannel` 早就声明了 `supports_streaming: bool`，并在
  `_handle_message` 里把它写进入站消息的 `metadata["supports_stream"]`。

- 但 `AgentService` 一直只用 `agent.ainvoke`（非流式），而
  `BaseChannel`/`ConsoleChannel` 也没有 `send_delta`/`send_delta_end` 的实现。

所以本次要做的事就是**接通这条链路**：

```
ConsoleChannel.start → _handle_message(supports_stream=True) → inbound queue
        │
AgentService._process(msg)   ← 看到 supports_stream
        │  走 agent.astream(stream_mode="messages")
        │  每个 AIMessageChunk 的文本 → OutboundMessage(event="delta")
        │  收尾 → OutboundMessage(event="stream_end")
        ▼
outbound queue → ChannelManager._dispatch_outbound
        │
        ├─ delta      → ConsoleChannel.send_delta  (逐段 print)
        └─ stream_end → ConsoleChannel.send_delta_end (补换行)
```

## 2. 改动点

### 2.1 `service.py` —— 调度器按需流式

[src/mini\_nanobot/service.py](../src/mini_nanobot/service.py)

- `_process` 根据入站消息的 `metadata["supports_stream"]` 分流：

  - 真 → `_process_stream`：用 `agent.astream(..., stream_mode="messages")`
    异步迭代，把每个 `AIMessageChunk` 的文本增量包成
    `OutboundMessage(event="delta")` 发到总线，结尾发一个
    `event="stream_end"`。

  - 假 → `_process_batch`：保持原 `ainvoke` 路径，发一个
    `event="final"`。

- `_extract_text_delta(chunk)`：从 chunk 里取出「该给用户看的文本」。

  - 只对 `AIMessage` / `AIMessageChunk` 生效——`ToolMessage`、
    `HumanMessage` 等一律丢弃，避免工具执行结果被当成回复吐给用户。

  - `content` 是 `str` 时直接返回；是 list（多模态/工具调用块）时
    只取 `{"type": "text" | "output_text"}` 块的 `text` 拼接，
    跳过 `tool_use` 等非文本块。

- 错误统一走 `_reply_error`，发 `event="error"`。

- 顺手修了原代码里 `self.agent`（不存在）的 bug——改为 `self.runtime.graph`。

- `from .graph import AppRuntime` 放进 `TYPE_CHECKING`，让
  `service.py` 不再被 `graph.py` 的 sqlite saver 等重依赖拖累，
  便于单测。

### 2.2 `channels/base.py` —— 抽象出流式接口

[src/mini\_nanobot/channels/base.py](../src/mini_nanobot/channels/base.py)

新增两个带默认实现的方法（默认都是 no-op）：

- `send_delta(session_id, content, metadata)`

- `send_delta_end(session_id, metadata)`

契约：**声明** **`supports_streaming = True`** **的 channel 必须覆盖这两个方法**，
否则增量会被默认 no-op 丢弃。`supports_streaming = False` 的 channel
根本不会收到 `delta` 事件（service 会走 batch 路径），所以默认 no-op
是安全的。

### 2.3 `channels/console.py` —— 控制台逐 token 渲染

[src/mini\_nanobot/channels/console.py](../src/mini_nanobot/channels/console.py)

- `supports_streaming = False` → `True`。

- `send_delta`：用 `_stream_started` 这个 set 记录某个 session
  是否已经打过头。第一个 token 来时先打 `bot> `                      前缀，之后每个片段
  用 `_console.print(content, end="", highlight=False, soft_wrap=True)`
  原样追加。`soft_wrap=True` 让 Rich 不要把整段重新排版、直接接着写，
  这样 token 是「一个字一个字往外蹦」的真实流式效果。

- `send_delta_end`：补一个换行，并把 session 从 `_stream_started`
  清掉，准备下一轮。

- `send`（非流式分支）保持原样，继续用 `Markdown` 渲染整条回复。

同时修了几个本来就让控制台跑不起来的 bug：

- `start()` 现在会先调用 `_restore_active_session()`，否则 `session_id`
  一直是空串，第一句话发出去就丢。

- `/new` 之前写成 `self.session_id = self._create_session()`，但
  `_create_session` 返回 `None`——改成直接调用，靠方法内部赋值。
  （`_create_session` 仍负责创建并激活新会话。）

### 2.4 顺带修的阻塞性 bug

为了让流式真正能跑起来（否则连启动都启动不了），修了三处早已存在的 bug：

| 文件                                                           | 问题                                                                                                              | 修复                                                       |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| [graph.py](../src/mini_nanobot/graph.py)                     | `memory = MemoryBackend(...)` 直接实例化 Protocol，`TypeError: Protocols cannot be instantiated`                      | 改成 `FileMemoryBackend(...)`                              |
| [cli.py](../src/mini_nanobot/cli.py)                         | 先 `service = AgentService(bus)` 缺 `runtime` 参数必崩；`cfg.data_dir` 不存在                                             | 删掉死代码行；`cfg.data_dir` → `cfg.workspace_dir`              |
| [session/manager.py](../src/mini_nanobot/session/manager.py) | `_normalise` 的 `return` 缩进在 `for` 里，空 sessions 时返回 `None` 导致构造失败；同时类里有个 `list` 方法遮蔽内置 `list`，`list[...]` 注解求值报错 | `return` 提到循环外；文件头加 `from __future__ import annotations` |

## 3. 关键代码片段

**流式调度**（`service.py`）：

```python
async def _process_stream(self, msg: InboundMessage) -> None:
    stream = self.runtime.graph.astream(
        {"messages": [HumanMessage(content=msg.content)]},
        config={"configurable": {"thread_id": msg.session_id}},
        context=AgentContext(session_id=msg.session_id, memory=self.runtime.memory),
        stream_mode="messages",
    )
    async for chunk, meta in stream:
        text = self._extract_text_delta(chunk)
        if text:
            await self.bus.publish_outbound(
                OutboundMessage(channel=msg.channel, session_id=msg.session_id,
                                content=text, event="delta"))
    await self.bus.publish_outbound(
        OutboundMessage(channel=msg.channel, session_id=msg.session_id,
                        content="", event="stream_end"))
```

**控制台逐 token 输出**（`console.py`）：

```python
async def send_delta(self, session_id, content, metadata=None):
    if not content:
        return
    if session_id not in self._stream_started:
        _console.print("[bold magenta]bot>[/bold magenta] ", end="")
        self._stream_started.add(session_id)
    _console.print(content, end="", highlight=False, soft_wrap=True)

async def send_delta_end(self, session_id, metadata=None):
    self._stream_started.discard(session_id)
    _console.print()
```

## 4. 为什么用 `stream_mode="messages"`

LangGraph 的编译图支持多种 `stream_mode`：

- `values` / `updates` —— 每步把**整个 state** 或 step diff 吐出来，
  粒度太粗，token 级流式用不上。

- **`messages`** —— 每次 LLM 产出一个 message chunk 就立刻 yield
  `(chunk, metadata)`，正好是 token 流。`metadata["langgraph_node"]`
  还能告诉我们这段是 `model` 节点还是 `tools` 节点出来的。

- `custom` / `debug` 等与本需求无关。

实测（langchain 1.3.11 / langgraph 1.2.7）一个会话输出形如：

```
TUPLE AIMessageChunk 'You'    node= model
TUPLE AIMessageChunk ' are'   node= model
TUPLE AIMessageChunk ' great' node= model
TUPLE AIMessageChunk '!'      node= model
TUPLE AIMessageChunk ''       node= model      # 收尾空 chunk
```

## 6. 如何启用 / 接入新 channel

- 控制台：已默认开启（`ConsoleChannel.supports_streaming = True`）。

- 新 channel（比如以后接 Telegram）只需：

  1. `class XxxChannel(BaseChannel)` 里设 `supports_streaming = True`；
  2. 覆盖 `send_delta` / `send_delta_end`，把 `content` 增量用平台 API 发出去；
  3. 不用动 `AgentService` 和 `MessageBus`——它们只认 `event`。

## 7. 设计取舍与限制

- **流式时不做 Markdown 渲染**：`send_delta` 直接原样追加文本。
  原因是 Rich 的 `Markdown` 需要完整文本才能排版，逐 token 重新渲染会
  闪烁/抖动。非流式 `send` 仍走 `Markdown`。如以后想要「边流边渲染」，
  可以在 `send_delta` 里用 `rich.live.Live` 维护一个会话级 buffer，
  但复杂度上升明显，先不做。

- **持久化不受影响**：流式只影响「给用户看」的过程，对话 checkpoint
  仍由 `AsyncSqliteSaver` 在 `astream` 结束后正常落库。

- **工具调用过程不外露**：`_extract_text_delta` 只放行 `AIMessage*`
  的文本块，工具入参/结果不会以 `delta` 形式发给前端。

- **错误处理**：`AgentService.run` 仍用顶层 try/except 兜底，异常时
  发 `event="error"` 的出站消息，会被 dispatcher 当作普通 `send` 打印。
